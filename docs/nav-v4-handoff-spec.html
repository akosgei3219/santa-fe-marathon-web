01

Where the header comes from

Elementor's header location does not render on this install, so the header is authored as a single HTML widget inside footer template 2365 and moves itself into place at runtime. A developer reading the page source before JavaScript runs will find the header near the bottom of the document.

  • Relocation. On load the script inserts #sitenav-wrap as the first child of <body>, so tab order and landmark order match the visual order. Layout does not depend on the move, because both tiers are position:fixed.
  • Homepage opt-out. When body.home is present the script removes #sitenav and #sitenavMobile from the DOM and returns. The homepage ships its own React navigation, aligned to the same information architecture but built separately.
  • Skip links win the first slot. An accessibility pass runs later and inserts nav.sfhm-skiplinks ahead of the wrapper, so the wrapper ends up second in the body. That is expected.

Everything in the widget is scoped under #sitenav-wrap. Treat that ID as the isolation boundary: nothing inside it should be styled from a page stylesheet, and the widget should not style anything outside it beyond the documented body rules.

08

Bilingual contract

The header is fully bilingual with no i18n library. Every translatable node carries both strings as attributes, and the toggle swaps textContent.

<span class="mx-name"
      data-en="Course Highlights &amp; Elevation"
      data-es="Atractivos del recorrido y elevaci&oacute;n">Course Highlights &amp; Elevation</span>

126 element pairs are live and every one of them matches its own rendered text, so a toggle to Spanish and back is lossless. Four rules keep it that way.

  1. Never put data-es on an element that has child elements. The toggle sets textContent, which would destroy the children. A link with a descriptor must carry its label in a child span and leave the anchor itself untranslated.
  2. Write accents as numeric HTML entities inside the attributes. Backslash-u escapes do not survive the WordPress slashing round trip.
  3. Keep the literal text and data-en identical. They are two independent copies of the same string, and only the toggle reconciles them. If they drift, the label silently changes the first time someone switches language.
  4. The toggle persists to localStorage under sfhm-lang and sets the document lang attribute to es-US or en-US.

The Concierge reuses this mechanism rather than duplicating it: its 23 fact rows are hidden spans carrying data-en and data-es inside the wrapper, so the toggle translates them for free and the script simply reads textContent at query time. Keyword lists use | as the delimiter, never a comma, because one keyword is "7,000".

10

Accessibility

What is already correct

  • Focus order matches visual order because the wrapper relocates to the top of the body. Skip links sit ahead of it.
  • Triggers are buttons with aria-haspopup="true", aria-expanded, and aria-controls wired at runtime to sitenav-mega-0 through -2.
  • Panels are properly hidden when closed. visibility:hidden keeps their links out of the tab order.
  • Landmarks are labeled. Main navigation, Account, Mobile menu, Language group, Skip links.
  • Current page is marked with aria-current="page" on any anchor whose normalized path matches the URL. The root path is excluded so the brand link never claims to be current.
  • Escape closes panels and the drawer from anywhere on the page.
  • The Concierge dialog moves focus to its input on open and returns it to the trigger on close.
  • Focus is always visible: a 2px gold outline at 3px offset on every link and button in the header and drawer.

Gaps a developer should close

  • The Concierge dialog does not trap focus. It has role="dialog" and a labelling heading, but Tab can walk out of it into the page behind. It also lacks aria-modal="true".
  • The drawer does not trap focus either, and the page behind it remains tabbable while it is open. Background scroll is locked, but focus is not.
  • Two touch targets fall short of 44px on phones. See section 13.
  • Panels have no arrow-key navigation. This is acceptable for a disclosure pattern with buttons, but worth a decision if the menu is ever announced as a menubar.
  • Most motion ignores prefers-reduced-motion.
11

Content rules and edge cases

Editorial rules that constrain the markup

  • No emoji and no arrows anywhere on the website. Inline SVG or nothing. Watch for escaped characters sneaking in through Elementor JSON.
  • Discount codes and percentages are email-only. They must never appear in the header, a mega panel, or a Concierge fact card. Hotel codes are the only exception, and they live on the lodging page.
  • Credit artists by name wherever their work is referenced.
  • The Store chip stays inert until a store page actually exists.

Length and overflow

  • Sub-link names run to about 33 characters today ("Age-Group Divisions & Medallions"). At 280px column width and 17px Anton they wrap to two lines cleanly. There is no truncation and none should be added; wrapping is the intended behavior.
  • Spanish runs longer than English, routinely by 15 to 30 percent. Every layout decision must be checked in Spanish, not only English. "Logistica de la semana de carrera" is the current worst case.
  • Trigger labels do not wrap (white-space:nowrap). A fifth top-level track, or a longer label than "Experience Santa Fe", will overflow before the 980px breakpoint catches it.
  • Descriptors are single-purpose fact lines. Keep them under about 45 characters so they hold one line at 1280px.

Edge cases

  • JavaScript disabled. Panels still open on hover and focus. The language toggle, click-toggle, drawer, active-page marking and Concierge do not work, and the header does not relocate, so it renders near the bottom of the page. Layout is unaffected because both tiers are fixed.
  • Homepage. The widget deletes itself. Any change made here must be mirrored by hand into the React navigation, which is a separate implementation.
  • Long page with an anchor link. Four nav destinations are homepage anchors. From an inner page these navigate away and then jump, landing under the 122px fixed stack unless the target has scroll padding.
  • Concierge with an empty query. Results are cleared and nothing renders. The hint line stays visible.
  • Concierge with no keyword match. One fallback card to the contact page.
  • Slow connection. Anton and Hanken Grotesk load from Google Fonts with display=swap, so the header paints in the fallback stack first. Anton has no close metric match, so expect visible reflow in the brand and sub-link names.
  • Missing card image. The Register card's image has a fixed 16:9 aspect ratio, so a failed load leaves a correctly sized gap rather than collapsing the card.
12

Build and deploy constraints

These are properties of the delivery mechanism, not the design, and they have all cost real time before.

  • Scripts must be ASCII with zero angle brackets. Elementor's HTML widget truncates at tag-like strings. That rules out arrow functions, comparison operators and template literals building markup. Use function keywords, Math.sign(a-b) comparisons, and createElement with textContent. Assert the constraint before every write.
  • The Concierge script is deliberately last. If Elementor ever truncates the widget, it cuts that script rather than the navigation machinery. Any new script goes after it, and the widget must still end with a closing script tag and the wrapper's closing div.
  • Writes can report success without persisting. Always re-read the widget and assert a marker string before treating a deploy as done.
  • Two cache layers. Purge Elementor files and the WP-Optimize page cache. Skipping either shows a stale header and fakes a failed deploy. In the WP-Optimize interface only the plain purge button works; the all-pages variant silently does nothing.
  • Verify logged out. Administrators bypass the page cache, so an admin view proves nothing.
  • Never retype the widget. Cut existing fragments and reassemble, so each link's English string, Spanish string, entities and href travel together. Guard on zero lost hrefs, an unchanged script block, no loss of data-es count, and per-tag open/close balance.
  • Do not use a naive angle-bracket balance check on this widget. The CSS contains child combinators, so it always fails. Per-tag deltas are the correct guard.
  • ElementsKit is active again and injects its own hamburger rules at 1024px and below. It does not currently collide with this header, but it is a live source of conflict for anything added to the bar.
13

Open decisions

Six things surfaced while measuring the live header. Two have been fixed on template 2365 and verified logged out. Two remain open. Two are confirmations that something odd is intentional.

The Register pill hid 80px earlier than documented Fixed

The two-tier notes said the pill hides at 520px and below. It was hiding at 600px, because an older rule carried !important and nothing could un-hide it in between:

/* before */
@media (max-width:600px){ #sitenav-wrap .nav-cta{display:none !important} }
@media (max-width:520px){ #sitenav-wrap .nav-right .nav-cta{display:none} }   /* never fired */

/* after: the .nav-cta declaration is gone from the 600px block */
@media (max-width:600px){ #sitenav-wrap .nav-right{gap:10px}
                          #sitenav-wrap .brand span{display:none} }
@media (max-width:520px){ #sitenav-wrap .nav-right .nav-cta{display:none} }   /* now governs */

Resolved as 520. The IA v4 migration deliberately moved the pill into .nav-right and recorded it as visible on mobile down to 520px; the 600px rule predates that work. Removing the !important alone would not have helped, because the 600px rule would still have matched. Verified: Register renders 106 by 48px at 560px, and is display:none at 500px.

Two touch targets are below 44px on phones Accessibility

A global (pointer:coarse) rule sets min-height:44px on language buttons, but the ribbon compression rule overrides it from a higher-specificity ID selector. The result measures 32 by 19px. The Concierge button measures 37 by 36px.

#sitenav-wrap .ribbon .lang-btn{min-height:0;min-width:0;height:auto;padding:2px 8px}

Fix: keep the visual size but grow the hit area, with padding on a wrapper or a pseudo-element that extends the target past the ribbon's 31px band. Removing the compression rule is not an option: it is what keeps the ribbon at 31px instead of inflating to 48px.

The brand mark's declared height never applied Fixed

The header declared a 67 by 60px mark. A sitewide html body img{height:auto!important} rule won and the logo rendered 67 square, so the declaration was fiction and the bar was 7px taller than the stylesheet implied.

#sitenav-wrap .brand .mark{width:67px;height:auto;flex:none;display:block;border-radius:8px;object-fit:contain}

Resolved by making the declaration truthful, not by forcing 60px. Winning that fight would have shrunk the bar from 91 to 84px on every page and required retuning the body offset from 122px, which is a design change nobody asked for. The source asset is 500 square, so nothing is distorted. Zero visual change: the mark measures 67 by 67 before and after.

The --navh token is 3px short Stale

The token reads 119px. The measured stack is 122px, which matches the body padding. Nothing currently reads the token, so this is latent rather than live.

Fix: set it to 122px and use it for the body padding, so the two values cannot drift again.

The Register card is invisible on tablets By design

Between 980 and 1100px the desktop menu is still showing, but the Secure Your Spot card is hidden. This was a deliberate call: at three columns the card had nowhere to sit, and the Register pill in the bar still covers the action.

Do not "fix" this without asking. If it should return, the panel needs a two-by-two layout at that width, not a fourth column.

Store is not a link By design

No store page exists and the wearable-art line has no pre-order URL. The chip is an inert span at 50% opacity so it cannot be tabbed to or clicked. It becomes an anchor only when there is a real destination.
